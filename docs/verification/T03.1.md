## 3. 设计要点

### 3.1 抽象基类

T03.1 用 `abstract class AppException implements Exception` 作为所有自定义异常的根：

```dart
abstract class AppException implements Exception {
  const AppException({
    required this.code,
    required this.message,
    this.cause,
    this.stackTrace,
  });

  final String code;
  final String message;
  final Object? cause;
  final StackTrace? stackTrace;

  @override
  String toString() => '$runtimeType(code: $code, message: $message)';
}
```

- **`implements Exception`**：保证 `throw` 与 `catch (Exception e)` 工作
- **四公共字段**：`code`（业务/HTTP 错误码）、`message`（人类可读）、`cause`（底层原始异常）、`stackTrace`（调试栈）
- **`const` 构造**：子类可作为 `const` 字面量使用

### 3.2 6 个具体子类

T03.1 定义了 6 个具体子类，每个对应一类错误场景（spec 要求 4 个 + 2 个补充）：

| 类 | 默认 `code` | 额外字段 | 典型场景 |
|---|---|---|---|
| `NetworkException` | `NETWORK` | — | 断网、超时、TLS、DNS |
| `ServerException` | （必传） | `int? statusCode` | 5xx、业务码非 0 |
| `CacheException` | `CACHE` | — | SharedPreferences/Hive/Isar 失败 |
| `UnauthorizedException` | `UNAUTHORIZED` | — | 401、token 失效、强制登出 |
| `ValidationException` | `VALIDATION` | `String? field` | 表单校验失败 |
| `UnknownException` | `UNKNOWN` | — | 兜底分类 |

`ServerException` 与 `ValidationException` 重写 `toString` 以输出额外字段（statusCode / field）。

### 3.3 spec 偏差说明

spec 列举了 4 个 Exception（Network/Server/Cache/Unauthorized）并加 "等" 字。T03.1 补充了 `ValidationException`（与 T03.2 的 ValidationFailure 对应）和 `UnknownException`（兜底），实现「Exception → Failure」一一对应。
