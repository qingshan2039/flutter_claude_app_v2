# T23.2 更新策略 — 验证报告

> 任务 T23.2 / 模块 M23 应用内更新 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T23.2 实现更新弹窗 `UpdateDialog` + `showUpdateDialog`，落地**强制/提示/静默**三档：强制（`PopScope(canPop:false)` + `barrierDismissible:false` + 无「稍后」）、提示（可「稍后」返回 false / 「立即更新」返回 true）、静默（不弹窗，由调用方走后台流程）。策略由 T23.1 `UpdateManager` 推出。demo 页可一键演示四种场景。4 个 widget 测试全绿。

## 1. 任务目标（来自 spec）

T23.2（spec 911-914）：强制/提示/静默 三档 + 更新弹窗 UI，交付物更新弹窗组件。

## 2. 实际配置

| 档位 | 行为 |
|---|---|
| force（强制） | `PopScope(canPop:false)` 屏蔽返回；`barrierDismissible:false`；无「稍后」；额外红字提示 |
| optional（提示） | 「稍后」(pop false) / 「立即更新」(pop true) |
| silent（静默） | 不弹此对话框（调用方后台下载，UI 不打扰） |
| upToDate | 不弹窗 |
| 内容 | 最新版本 + 当前版本 + releaseNotes |

## 3. 快速上手（Quick Start）

```dart
final decision = await getIt<UpdateManager>().check(current: AppVersion.parse('1.3.0'));
if (decision.updateAvailable && decision.policy != UpdatePolicy.silent) {
  final goUpdate = await showUpdateDialog(context, decision);
  if (goUpdate) { /* 走平台更新通道（T23.3/4/5） */ }
}
```

showcase「M23 应用内更新」→「更新策略决策」可点四个场景按钮体验。

## 5. 与 spec 的偏差与决策

T23.2 决策：弹窗只负责「展示 + 收集用户意图（是否更新）」，**不耦合**具体更新动作——「立即更新」后由调用方按平台分发到 T23.3/T23.4/T23.5。强制档用 `PopScope`（替代废弃的 WillPopScope）+ `barrierDismissible:false` 双重锁死，确保无法绕过。
