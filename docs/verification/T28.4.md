# T28.4 配置缓存与刷新 — 验证报告

> 任务 T28.4 / 模块 M28 远程配置与 Feature Flag / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T28.4 在 `DefaultRemoteConfig` 内实现配置**本地缓存与刷新**：构造时从 `KeyValueStorage` 加载上次激活值（离线/首启即生效），`fetchAndActivate()` 拉取后写回缓存并返回是否变化。建议 `bootstrap` 启动时调用一次刷新（失败用旧缓存/默认值，不阻塞启动）。缓存读写/刷新由单测覆盖。

## 1. 任务目标（来自 spec）

T28.4（spec 1054-1057）：本地缓存 + 启动时刷新，交付物配置刷新逻辑。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 本地缓存 | KeyValueStorage key `remote_config.cache` 存 JSON；构造时 `_loadCache()` 加载 |
| 损坏容错 | `jsonDecode` 失败 → 忽略缓存，回退默认值 |
| 刷新 | `fetchAndActivate()`：client.fetch → 写回缓存 → 返回 changed（mapEquals 对比） |
| 启动刷新 | 建议在 `bootstrap` 调用（非关键路径，失败不影响启动） |
| 优先级 | 已激活/缓存值 > 内置默认值 |

## 3. 快速上手（Quick Start）

```dart
// bootstrap 启动时（非关键路径）：
unawaited(getIt<RemoteConfig>().fetchAndActivate());
// 离线/首启：自动用缓存或默认值，无需联网即可读取。
```

## 5. 与 spec 的偏差与决策

T28.4 决策：缓存复用 `KeyValueStorage`（已有、轻量），缓存与默认值/激活值的回退顺序固定为「激活/缓存 > 默认」；刷新返回 `changed` 便于上层决定是否刷新 UI；启动刷新放非关键路径（不阻塞首帧，与 M13 bootstrap 设计一致）。
