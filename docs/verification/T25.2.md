# T25.2 本地变更队列 — 验证报告

> 任务 T25.2 / 模块 M25 离线优先架构 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T25.2 实现 `SyncQueue`（@lazySingleton）：把离线写操作 `PendingOperation` 持久化入队（KeyValueStorage JSON），恢复在线后 `flush(handler)` 逐个重放——成功移除、失败保留并 `retryCount+1`。配合 `ConnectivityService`（T25.4）在网络恢复时触发。5 个单测全绿。

## 1. 任务目标（来自 spec）

T25.2（spec 974-977）：离线操作队列 + 上线后同步，交付物同步队列模块。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 操作模型 | `PendingOperation{id, type, payload, createdAt, retryCount}` + toJson/fromJson/copyWith |
| 入队 | `enqueue(op)`；`all()`/`length`/`isEmpty`/`remove(id)`/`clear()` |
| 持久化 | KeyValueStorage 单 key 存 JSON 数组（跨实例可见） |
| 上线同步 | `flush(handler)`：成功移除、失败保留 retry+1、handler 抛错计失败 |
| 报告 | `SyncReport{synced, failed}` |

## 3. 快速上手（Quick Start）

```dart
// 离线时入队
await getIt<SyncQueue>().enqueue(PendingOperation(
  id: uuid, type: 'createPost', payload: {...}, createdAt: DateTime.now(),
));
// 网络恢复（监听 networkStatusProvider）时同步
final report = await getIt<SyncQueue>().flush((op) => api.replay(op));
```

## 5. 与 spec 的偏差与决策

T25.2 决策：队列持久化用 KeyValueStorage（轻量、已有），操作 payload 用 `Map<String,dynamic>`（JSON 友好、业务自定义 type）；`flush` 接收 handler 回调解耦具体重放逻辑；失败累加 retryCount 便于上层做退避/上限策略。触发时机交给 T25.4 网络监听。
