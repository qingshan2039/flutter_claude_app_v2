## TL;DR

T32.4 交付面向主流 AI 编码助手的统一规则文件：`CLAUDE.md`（权威详版）、`.cursorrules`（Cursor）、`.github/copilot-instructions.md`（GitHub Copilot）三处同源，外加人类视角的 `docs/ai/AI_ASSISTED_DEV.md` 总览。内容把本仓库的架构分层、技术选型、**injectable/codegen 三个坑**、编码/测试/提交约定与「每任务写验证报告」流程前置给 AI，使 Cursor/Claude/Copilot 生成的代码自动贴合项目规范。

## 1. 任务目标（来自 spec）

T32.4（spec 1149-1152）：`.cursorrules` 模板 + Claude Code / Copilot 配置，交付物 AI 开发配置。

## 2. 实际配置

| 文件 | 工具 | 角色 |
|---|---|---|
| `CLAUDE.md` | Claude Code / Claude | **权威详版**（架构/选型/坑/命令，10 节） |
| `.cursorrules` | Cursor | 精简同步版（开仓库自动加载） |
| `.github/copilot-instructions.md` | GitHub Copilot | 精简同步版（Instruction Files 生效） |
| `docs/ai/AI_ASSISTED_DEV.md` | 人类 | 总览：文件清单/启用方式/协作流程/坑位 |

核心内容（三份同源）：分层 domain→data→presentation + feature 隔离；选型 get_it/injectable·riverpod·go_router·freezed·dio·very_good_analysis；**三坑**（injectable 不吃基本类型构造参数；`@disposeMethod` 接口须声明 dispose；`flutter analyze` 不查生成代码须再 `flutter test`）；`const` 优先 / Result<T> 不抛异常 / 不盲目 `dart fix --apply`；测试复用 `test/_helpers/` + ProviderScope；交付走 `docs/verification/T{XX.X}.md` + Conventional Commits。

## 3. 快速上手（Quick Start）

- Cursor：打开仓库自动读 `.cursorrules`。
- Claude Code：仓库根运行自动读 `CLAUDE.md`。
- Copilot：VS Code 启用 *Use Instruction Files* 后读 `.github/copilot-instructions.md`。
- 改约定时三份规则一起更新（以 `CLAUDE.md` 为准），完整规范仍以 `docs/CONVENTIONS.md` 为最终依据。

## 5. 与 spec 的偏差与决策

T32.4 决策：（1）spec 仅点名 `.cursorrules` 与 Copilot 配置，本实现额外补 `CLAUDE.md`（项目已用 Claude 协作，作为**权威源**）与人类向 `docs/ai/AI_ASSISTED_DEV.md`，形成「三助手同源 + 一份总览」；（2）三份助手规则**保持同源、精简前置**，完整规范仍指向既有 `docs/CONVENTIONS.md`/`docs/ARCHITECTURE.md`，避免重复维护漂移；（3）把本仓库实战踩过的 injectable/codegen 三坑与「不要盲目 `dart fix --apply`」红线写进规则，这是 AI 在本项目最易犯错处。这些是纯文档/配置交付，不引入运行时代码与依赖。
