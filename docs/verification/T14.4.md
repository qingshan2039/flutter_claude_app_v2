# T14.4 下拉刷新 / 上拉加载 — 验证报告

> 任务 T14.4 / 模块 M14 通用 UI 组件 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T14.4 在 `lib/shared/widgets/app_refresh_list.dart` 用 `easy_refresh` 封装 `AppRefreshList<T>`：声明式入参（items / onRefresh / onLoad / hasMore / itemBuilder），空列表回退 `EmptyWidget` 且仍可下拉；showcase M14 demo 用 Riverpod `AutoDisposeNotifier` 持有分页状态演示联动。新增依赖 `easy_refresh: ^3.5.0`。

## 1. 任务目标（来自 spec）

T14.4 要求封装 easy_refresh 或 pull_to_refresh，实现下拉刷新/上拉加载，与 Riverpod 联动，交付刷新组件 + 列表示例（spec 599-603 行）。

## 2. 实际配置

| spec 期望 | 实际实现 |
|---|---|
| 封装 easy_refresh / pull_to_refresh | 选 `easy_refresh: ^3.5.0`（活跃维护）；`AppRefreshList<T>` |
| 与 Riverpod 联动 | 组件本身只收回调（解耦）；联动在 demo：`_pagedProvider`（AutoDisposeNotifier）的 `refresh()`/`loadMore()` |
| 列表示例 | `_RefreshListDemoPage`（ui_kit_demo_page.dart）：15→45 项分页，到底显示「没有更多」 |

## 3. 快速上手（Quick Start）

```dart
AppRefreshList<Item>(
  items: state.items,
  hasMore: state.hasMore,
  onRefresh: () => ref.read(p.notifier).refresh(),
  onLoad: () => ref.read(p.notifier).loadMore(),
  itemBuilder: (_, item, _) => ListTile(title: Text(item.title)),
);
```

`hasMore` 为 false 时上拉到底返回 `IndicatorResult.noMore`（footer 显示「没有更多」）。

注：测试用 `pumpAndSettle` 排空 EasyRefresh 首帧弹道（ballistic）产生的 0 时长 Timer（`IndicatorNotifier._updateBySimulation` 在轴向首次确定时 `Future(...)`），否则报「A Timer is still pending」。

## 5. 与 spec 的偏差与决策

T14.4 决策：在 easy_refresh 与 pull_to_refresh 间选 easy_refresh 3.5.0——pull_to_refresh 已多年未更新、与新 Flutter 兼容性差。组件设计为「只收回调、不依赖 Riverpod」，让刷新 UI 与状态管理解耦；Riverpod 联动在 demo 中演示。
