# T27.3 自动曝光埋点 — 验证报告

> 任务 T27.3 / 模块 M27 数据埋点 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T27.3 实现 `ExposureTracker`：用 `visibility_detector` 监测子元素可见比例，首次达到阈值（默认 0.5）时上报一次 `element_exposure` 事件（[AnalyticsEvent.exposure]）+ 回调 `onExposed`，**只触发一次**避免反复滚动重复上报。引入 `visibility_detector` 0.4.0+2。2 个 widget 测试全绿。

## 1. 任务目标（来自 spec）

T27.3（spec 1025-1028）：VisibilityDetector 集成 + 元素曝光上报，交付物曝光埋点组件。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 组件 | `ExposureTracker({exposureName, child, threshold=0.5, onExposed, analytics, extraParams})` |
| 检测 | `VisibilityDetector(key, onVisibilityChanged)`；`visibleFraction >= threshold` 触发 |
| 只触发一次 | `_fired` 标志位 |
| 上报 | `analytics.track(AnalyticsEvent.exposure(name))`（analytics 缺省取 `getIt<Analytics>()`） |
| 依赖 | `visibility_detector: ^0.4.0+2` |

## 3. 快速上手（Quick Start）

```dart
ExposureTracker(
  exposureName: 'home_banner',
  child: BannerCard(),
);
```
showcase「M27 数据埋点」→ 横向滚动卡片即可看到曝光实时上报。

## 5. 与 spec 的偏差与决策

T27.3 决策：引入 `visibility_detector`（spec 点名，轻量稳定，`flutter pub add` 无冲突）；曝光只报一次（业务常见诉求）；与 T27.4 的 `AnalyticsEvent.exposure` + `track` 扩展集成。**测试注意**：VisibilityDetector 默认 500ms 节流会在 widget 销毁后留下 pending Timer 触发断言；测试需把 `updateInterval` 置 0（showcase 画廊测试 setUp 也已设置）。
