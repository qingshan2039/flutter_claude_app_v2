### 3.1 统一回调签名

所有错误源共用 `ErrorReporter`：

```dart
typedef ErrorReporter = void Function(Object error, StackTrace stackTrace);
```

默认 `_defaultReporter` 用 `debugPrint`；M11/T11.4 接 Sentry 后会替换。所有公开 API 都接受可选 `reporter` 参数，便于测试注入与生产替换。

### 3.2 isolate 消息解析独立成顶层函数

```dart
({Object error, StackTrace stackTrace})? parseIsolateMessage(Object? data) {
  if (data is! List) return null;
  if (data.length != 2) return null;
  final error = data[0] ?? 'Unknown isolate error';
  final stackString = data[1] as String? ?? '';
  return (error: error, stackTrace: StackTrace.fromString(stackString));
}
```

- 设计原因：`listenIsolateErrors` 内部调用 `Isolate.current.addErrorListener`，**修改全局状态**，在 flutter_test 环境不易隔离测试。把解析逻辑抽出来后，可纯函数式断言所有边界情况（null / 非 List / 长度异常 / 字段缺失）
- 返回 Dart 3 record `({Object error, StackTrace stackTrace})`，调用点直接解构

## 4. 推荐启动顺序

`main.dart` / `bootstrap.dart` 推荐顺序（M13/T13.1 接入）：

```dart
void main() {
  runAppGuarded(() {
    WidgetsFlutterBinding.ensureInitialized();
    registerGlobalErrorHandlers();
    listenIsolateErrors();
    runApp(const MyApp());
  });
}
```

层次：

1. 最外层 `runAppGuarded` 提供 zone 兜底
2. binding 初始化后立即装 FlutterError/PlatformDispatcher
3. 再装 isolate listener
4. 最后 runApp

层层覆盖，确保任何路径异常都至少被一个 handler 拿到。

### 5.3 运行调用

测试 `runAppGuarded: zone 内的异步异常被 reporter 捕获` 实际执行：

```dart
Object? capturedError;
final completer = Completer<void>();

runAppGuarded(
  () {
    Future<void>.delayed(const Duration(milliseconds: 1), () {
      throw Exception('zone-error');
    });
  },
  reporter: (e, s) {
    capturedError = e;
    if (!completer.isCompleted) completer.complete();
  },
);

await completer.future.timeout(const Duration(seconds: 2));
expect(capturedError.toString(), contains('zone-error'));   // ✅
```

测试 `PlatformDispatcher.onError 触发 reporter 并返回 true`：

