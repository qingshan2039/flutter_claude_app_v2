## 2. 设计要点

### 2.1 接口与两个实现

| 类 | 用途 | 注册到 DI |
|---|---|---|
| `SecureStorage`（abstract） | 接口契约 | — |
| `FlutterSecureStorageImpl` | 生产：iOS Keychain / Android EncryptedSharedPreferences | ✅ `@LazySingleton(as: SecureStorage)` |
| `InMemorySecureStorage` | 测试 / 桌面 fallback | ❌ 不注册（测试中手动 new） |

### 2.2 Android 选项：encryptedSharedPreferences

flutter_secure_storage 默认在 Android 用 Keystore，但 Keystore 在低端设备 / 系统更新后偶有失效。`encryptedSharedPreferences: true` 改用 AndroidX 的 EncryptedSharedPreferences，更稳定。代价：用户清缓存会清掉数据（但这反而是合理行为）。

### 2.3 iOS 选项：first_unlock_this_device

`KeychainAccessibility.first_unlock_this_device` 表示：设备首次解锁后可访问，不随 iCloud 备份迁移。适合 token 类敏感数据。

### 2.4 SecureTokenStorage 替换链

T04.3 时 [InMemoryTokenStorage] 是 `TokenStorage` 的 DI 绑定（占位）。T05.2 完成后：

```diff
- @LazySingleton(as: TokenStorage)
- class InMemoryTokenStorage implements TokenStorage { ... }
+ class InMemoryTokenStorage implements TokenStorage { ... }   // 保留类体，无 DI 注解

+ @LazySingleton(as: TokenStorage)
+ class SecureTokenStorage implements TokenStorage {
+   SecureTokenStorage(this._storage);
+   final SecureStorage _storage;
+   // 持久化到 'auth.access_token' / 'auth.refresh_token'
+ }
```

`getIt<TokenStorage>()` 现在返回 `SecureTokenStorage`（包装 `FlutterSecureStorageImpl`）。

`InMemoryTokenStorage` 类体保留：在桌面端（无 secure storage 平台支持）或单测中可以手动 new 出来用作 fallback。

### 2.5 测试策略

`FlutterSecureStorageImpl` 依赖 platform channel，**unit test 不直接测**。改测 `InMemorySecureStorage`（验证抽象契约满足）+ `SecureTokenStorage`（用 `InMemorySecureStorage` 注入，验证业务逻辑）。
