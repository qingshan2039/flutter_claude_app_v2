# T27.4 事件埋点 API — 验证报告

## TL;DR

T27.4 实现 `AnalyticsEvent`（结构化事件：name + 不可变 params，断言非空名，`sanitizedParams()` 过滤 null）+ 便捷构造（`tap`/`exposure`）+ `AnalyticsX.track` 扩展（按规范上报）。配套**命名/参数规范**（snake_case、动词在前、值用基本类型、不发 null）写进代码注释。6 个单测全绿。

## 1. 任务目标（来自 spec）

T27.4（spec 1030-1033）：自定义事件上报 + 参数规范，交付物事件上报 API。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 结构化事件 | `AnalyticsEvent(name, {params})`：name 非空断言、params 不可变 |
| 参数规范 | `sanitizedParams()` 过滤 null；命名 snake_case、值基本类型（注释规范） |
| 便捷构造 | `AnalyticsEvent.tap(target)` → `button_click`；`AnalyticsEvent.exposure(element)` → `element_exposure` |
| 上报扩展 | `Analytics.track(event)` = `logEvent(event.name, params: event.sanitizedParams())` |

## 3. 快速上手（Quick Start）

```dart
getIt<Analytics>().track(AnalyticsEvent.tap('buy_button'));
getIt<Analytics>().track(
  AnalyticsEvent('add_to_cart', params: {'id': 'sku_1', 'qty': 2}),
);
```

## 5. 与 spec 的偏差与决策

T27.4 决策：事件 API 在 `Analytics.logEvent` 之上再加**结构化 `AnalyticsEvent` + 规范**，把命名/参数约定固化为代码（不可变 params、非空名断言、去 null），减少埋点脏数据；`track` 扩展让调用点简洁统一。
