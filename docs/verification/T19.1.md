# T19.1 登录模块 — 验证报告

> 任务 T19.1 / 模块 M19 示例业务模块 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T19.1 在 `features/auth/` 落地端到端登录：`LoginPage`（Form 表单校验）→ `LoginController`（AutoDisposeNotifier，AsyncValue 状态）→ `SignInUseCase` → `AuthRepositoryImpl.signIn`（调 DataSource → 存 Token → `Result<User>`）→ 成功置 `isLoggedInProvider=true` 并 `context.goNamed(home)`，失败用 `Result.fold` 归一化为 `Failure` 内联显示。验收：`flutter analyze` 0 issue、`flutter test`（含 auth 35 用例）全绿、dev APK 构建成功。

## 1. 任务目标（来自 spec）

T19.1（spec 760-766）：登录模块需覆盖**表单校验、网络请求、Token 存储、路由跳转、错误处理**，交付物 `features/auth/`。

## 2. 实际配置

| 关注点 | 实现 |
|---|---|
| 表单校验 | `LoginPage` 用 `Form`+`GlobalKey<FormState>`；`_validateEmail`（正则 `^[^@\s]+@[^@\s]+\.[^@\s]+$`）、`_validatePassword`（≥6 位） |
| 网络请求 | `AuthRemoteDataSource.signIn`（stub：300ms 延迟；password=='fail' 抛 `UnauthorizedException`，否则返回 `(user, accessToken, refreshToken)`） |
| Token 存储 | `AuthRepositoryImpl` 注入 `TokenStorage`，成功后 `tokenStorage.save(access, refresh)`；`signOut()` → `clear()` |
| 路由跳转 | 成功 `submit()` 返回 true → `context.goNamed(RouteNames.home)` |
| 错误处理 | Repository `try/catch Exception` → `errorMapper.map(e)` → `Failed`；`LoginController` 用 `Result.fold` 拆分，失败 `AsyncError(failure)`，页面 `_errorText` 取 `Failure.message` 内联红字 |
| 状态层 | `LoginController extends AutoDisposeNotifier<AsyncValue<void>>`，`loginControllerProvider` |

## 5. 与 spec 的偏差与决策

T19.1 决策：DataSource 为本地 stub（无真实后端），但完整走通「校验→请求→存 Token→跳转」链路，便于后续替换为真实 API；`AuthRepository` 接口扩充了 `signIn` / `signOut`（原仅 `getCurrentUser`），相应手写 fake（`_FakeRepo`/`_FakeAuthRepo`）补齐桩方法。`LoginController` 必须 `import core/error/result.dart` 才能用 `fold` 扩展方法（曾因缺失导致 analyze 报错，已修复）。
