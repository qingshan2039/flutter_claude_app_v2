## 2. 设计要点

### 2.1 envelope 数据类

```dart
class ApiResponse<T> {
  const ApiResponse({required this.code, this.message, this.data});

  factory ApiResponse.fromJson(
    Map<String, dynamic> json,
    T Function(Object? data) fromJsonT,
  ) => ApiResponse<T>(
    code: json['code'] as int,
    message: json['message'] as String?,
    data: json['data'] == null ? null : fromJsonT(json['data']),
  );

  static const int kSuccessCode = 0;

  final int code;
  final String? message;
  final T? data;

  bool get isSuccess => code == kSuccessCode;
  bool get isFailure => !isSuccess;
}
```

- **不使用 freezed**：单个 envelope 类不需要 copyWith / pattern matching；纯 Dart 更轻
- **不使用 @JsonSerializable**：泛型 + json_serializable 需要 `genericArgumentFactories`，配置复杂。手写 fromJson 更直接
- **`fromJsonT` 参数**：每个调用方提供具体数据类的反序列化函数；编译期类型安全

### 2.2 与 T04.4 ErrorInterceptor 的协作（"自动解包"的实质）

ApiResponse 本身只是数据类，**真正让上层"无感"的是 [ApiErrorInterceptor.onResponse]**：

```dart
@override
void onResponse(Response<dynamic> response, ResponseInterceptorHandler handler) {
  final data = response.data;
  if (data is Map && data.containsKey('code')) {
    final code = data['code'];
    if (code is int && code != ApiResponse.kSuccessCode) {
      handler.reject(DioException(
        ...,
        error: ServerException(code: code.toString(), message: ...),
      ));
      return;
    }
  }
  handler.next(response);
}
```

效果：
- 成功响应（code == 0）→ envelope 透传给 retrofit，retrofit 的 fromJson 直接处理 data 字段（约定 data 直接是目标 model 的 JSON）
- 失败响应（code != 0）→ 转 ServerException，上层 Repository 用 `on Exception catch (e)` 捕获

### 2.3 spec 偏差与折中

spec 期望"自动解包"。可能的实现策略：

| 策略 | 优点 | 缺点 |
|---|---|---|
| 拦截器替换 response.data 为 envelope.data | 上层完全无感 | 失败时 status code 不变（仍 200），调用方难分支 |
| 拦截器只 reject 业务失败，成功透传 | 错误处理统一为 Exception；retrofit 直接收 data | 后端必须坚守"data 就是目标 model"约定 |
| 包装层 `ApiResponse<T>` 显式 unwrap | 业务清晰，错误处理灵活 | 调用方写 `response.data.let { ... }` 样板代码 |

**T04.8 采用第 2 种**（拦截器只 reject 失败，成功透传）。`ApiResponse<T>` 类预留给需要显式访问 code/message 字段的特殊场景。
