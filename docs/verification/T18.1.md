# T18.1 敏感配置外部化 — 验证报告

> 任务 T18.1 / 模块 M18 安全规范 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T18.1 在 M15 `EnvConfig` 基础上新增 `apiKey`（经 `--dart-define=API_KEY` 注入、toString 脱敏），`env/*.example.json` 增 `API_KEY` 模板键；`SECURITY.md` 记录「密钥不入代码库」策略 + envied 可选方案。

## 1. 任务目标（来自 spec）

T18.1（spec 731-735）：API Key 通过 --dart-define 注入、envied 集成（可选），交付物配置示例 + 文档。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| API Key 注入 | `EnvConfig.apiKey` ← `String.fromEnvironment('API_KEY')`（resolve 阶段覆盖） |
| 脱敏 | `toString()` 把 `apiKey`/`sentryDsn` 显示为 `***`；`hasApiKey` getter |
| 不入库 | 真实 `env/*.json` gitignore；提交 `env/*.example.json`（含 `"API_KEY": ""`） |
| envied（可选）| SECURITY.md 文档化：需把密钥编译进二进制并混淆时使用 |

## 3. 快速上手（Quick Start）

```bash
cp env/prod.example.json env/prod.json     # 填入真实 API_KEY
flutter run --flavor prod -t lib/main_prod.dart --dart-define-from-file=env/prod.json
```
```dart
final key = ref.watch(envConfigProvider).apiKey;
```

## 5. 与 spec 的偏差与决策

T18.1 决策：复用 M15 的 `EnvConfig`（已是「外部化配置」对象）承载 `apiKey`，避免再造一套密钥类。envied **未集成**（默认 dart-define 更简单、CI 友好；envied 适合密钥必须随包分发的场景），在 SECURITY.md 文档化。强调：任何客户端方案都无法绝对防逆向，高敏感操作放服务端。
