## 2. 设计要点

### 2.1 CrashReporter 抽象 + 默认 Noop

```dart
abstract class CrashReporter {
  Future<void> recordError(Object error, StackTrace? stack, {bool fatal});
  Future<void> addBreadcrumb(String message, {String? category, Map? data});
  Future<void> setUser(String? id);
  Future<void> setTag(String key, String value);
}

@LazySingleton(as: CrashReporter)
class NoopCrashReporter implements CrashReporter { /* no-op */ }
```

DI 默认绑定 Noop（无 DSN 时安全）；M13 bootstrap 在 `SentryFlutter.init` 后 unregister + 重注册为 `SentryCrashReporter`。

### 2.2 SentryConfig.run 初始化

```dart
await SentryConfig.run(
  dsn: const String.fromEnvironment('SENTRY_DSN'),
  environment: 'prod',     // 环境标签
  appRunner: () => runApp(const MyApp()),
);
```

DSN 为空 → 直接 `appRunner()`（本地开发无需 Sentry）。非空 → `SentryFlutter.init` 自动捕获未处理异常 + 设环境标签 + tracesSampleRate。

### 2.3 breadcrumb / user / tag

`SentryCrashReporter` 委托 Sentry 静态 API：`captureException`（fatal → SentryLevel.fatal）、`addBreadcrumb`、`configureScope(setUser/setTag)`。

## 3. 实施过程的 Bug 修复（关键）

首版 `sentry_flutter: ^8.9.0`（解析 8.14.2）→ `flutter build apk` 失败：

```
Execution failed for task ':sentry_flutter:compileDebugKotlin'.
> Compilation error.
```

根因：项目 Kotlin 为 **2.2.20**（Flutter 3.41 默认），sentry_flutter 8.x 的 Kotlin 源码与 2.2 编译器不兼容。

**修复**：升级到 `sentry_flutter: ^9.0.0`（解析 9.20.0），9.x 已适配 Kotlin 2.2。我的 API 用法（captureException/addBreadcrumb/configureScope/SentryFlutter.init）在 9.x 兼容，`flutter analyze` 通过，APK 构建成功。

## 6. M03 / M06 / M07 衔接

`CrashReporter` 是 [GlobalErrorHandler]（M03/T03.5）`ErrorReporter` 回调的去处。M13 bootstrap 可：

```dart
registerGlobalErrorHandlers(reporter: (e, s) {
  getIt<AppLogger>().e('Uncaught', error: e, stackTrace: s);
  getIt<CrashReporter>().recordError(e, s, fatal: true);
});
```

ProviderObserver（M06）/ RouterLogObserver（M07）的事件也可转 `addBreadcrumb`。
