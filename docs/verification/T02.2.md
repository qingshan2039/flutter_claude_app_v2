## 4. 设计要点

T02.2 的 3 个核心文件示范了「Clean Architecture 数据层 ↔ 领域层」的标准三件套。

### 4.1 Entity（领域层，纯 Dart）

[lib/features/auth/domain/entities/user.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/features/auth/domain/entities/user.dart) 设计要点：

```dart
@freezed
sealed class User with _$User {
  const factory User({
    required String id,
    required String name,
    required String email,
    DateTime? createdAt,
  }) = _User;
}
```

- **纯 Dart**：不携带 `fromJson`/`toJson`，不依赖 `json_annotation`、Flutter、Dio
- **`sealed`**：freezed 3.x 要求 freezed class 显式声明 `sealed`/`abstract`/`interface`，支撑 Dart 3 的穷尽 pattern matching
- **freezed 自动提供**：value equality（`==`、`hashCode`）、`copyWith`、`toString`
- **不可变**：所有字段 `final`，构造函数 `const factory`

### 4.2 Model（数据层 DTO）

[lib/features/auth/data/models/user_model.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/features/auth/data/models/user_model.dart) 设计要点：

```dart
@freezed
sealed class UserModel with _$UserModel {
  const factory UserModel({
    required String id,
    required String name,
    required String email,
    @JsonKey(name: 'created_at') DateTime? createdAt,
  }) = _UserModel;

  factory UserModel.fromJson(Map<String, dynamic> json) =>
      _$UserModelFromJson(json);
}
```

- **`@JsonKey(name: 'created_at')`**：把后端 snake_case 字段映射到 Dart camelCase
- **`fromJson` factory**：触发 json_serializable 生成 `_$UserModelFromJson`
- **`toJson()`**：由 freezed + json_serializable 协同生成（无需手写）
- **不向上层暴露**：domain / presentation 层只见 `User`，不见 `UserModel`

### 4.3 Mapper（双向 extension）

[lib/features/auth/data/mappers/user_mapper.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/features/auth/data/mappers/user_mapper.dart) 设计要点：

```dart
extension UserModelToEntity on UserModel {
  User toEntity() => User(id: id, name: name, email: email, createdAt: createdAt);
}

extension UserEntityToModel on User {
  UserModel toModel() => UserModel(id: id, name: name, email: email, createdAt: createdAt);
}
```

- **extension 而非静态类**：调用点更自然 `model.toEntity()` 比 `UserMapper.toEntity(model)` 更易读
- **双向**：从后端来 `Model.toEntity`；提交回后端 `Entity.toModel`
- **roundtrip 一致性**：用 freezed 的 value equality 保证 `entity.toModel().toEntity() == entity`

## 7. 实施过程中遇到的问题与解决

T02.2 实施过程中遇到 1 个版本约束警告，已解决。

### 7.1 问题：`json_annotation: ^4.9.0` 触发 json_serializable 警告

- **现象**：第一次 `build_runner build` 输出：
  ```
  W json_serializable on lib/features/auth/data/models/user_model.dart:
    The version constraint "^4.9.0" on json_annotation allows versions before 4.12.0 which is not allowed.
  ```
- **根因**：`json_serializable 6.14.0` 在内部要求 json_annotation 至少 4.12.0；我最初的 `^4.9.0` 允许了较旧版本但实际锁定到 4.12.0，触发提示
- **修复**：把约束改为 `json_annotation: ^4.12.0`，与 json_serializable 当前要求严格对齐
- **教训**：codegen 生态的 annotation 包与 generator 包的版本约束要严格匹配；annotation 包通常需要 ≥ generator 包要求的最低版本

## 8. 与 spec 的偏差与决策

T02.2 实施未偏离 spec 字面，但有两个设计决策值得记录。

### 8.1 决策一：选择 freezed 3.x 而非 2.x

- **理由**: Dart 3 sealed class + pattern matching 是模板要长期使用的范式；freezed 3.x 原生支持
- **代价**: 所有 `@freezed` 类必须显式声明 `sealed`/`abstract`/`interface`（2.x 不需要）。模板维护者需在 T20.4 CONVENTIONS.md 写清楚

### 8.2 决策二：Mapper 用 extension 而非静态类

- **理由**: 调用点 `model.toEntity()` 比 `UserMapper.toEntity(model)` 自然；与 Dart 社区主流写法一致
- **代价**: 若需要 mapper 持有依赖（如 DateFormat 等），extension 写法会变形。届时（极少见）可降级为类 + injectable

### 8.3 决策三：Entity 不放 fromJson

- **理由**: Entity 必须保持「不知道 JSON」，跨数据源（REST / GraphQL / 本地缓存）可复用。若把 fromJson 放 Entity，data 层的 model 抽象就形同虚设
- **后果**: 每个领域对象都需要 Entity + Model 一对（外加 Mapper），文件数量增加。但分层收益显著大于额外的样板。
