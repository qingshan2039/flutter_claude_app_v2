# T17.3 Widget 测试示例 — 验证报告

> 任务 T17.3 / 模块 M17 测试体系 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T17.3 新增 `CurrentUserBadge`（监听 `currentUserProvider` 的三态组件）与其 widget 测试：通过 `ProviderScope.overrides` 注入 mocktail mock 的 `getCurrentUserUseCaseProvider`，精确驱动 data / error / loading 三态。

## 1. 任务目标（来自 spec）

T17.3（spec 692-696）：核心组件测试、Provider 注入测试，交付物 Widget 测试示例。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 被测组件 | `CurrentUserBadge`（`asyncUser.when(data/loading/error)`） |
| Provider 注入 | `ProviderScope(overrides: [getCurrentUserUseCaseProvider.overrideWithValue(mock)])` |
| 三态 | data（显示用户名）、error（「加载失败」）、loading（转圈，`pump()` 不 settle） |

> 既有大量 Widget 测试见 `test/shared/widgets/*`（M14 组件）。

## 3. 快速上手（Quick Start）

```dart
ProviderScope(
  overrides: [getCurrentUserUseCaseProvider.overrideWithValue(mockUseCase)],
  child: const MaterialApp(home: CurrentUserBadge()),
);
when(() => mockUseCase()).thenAnswer((_) async => const Success(User(...)));
```

## 5. 与 spec 的偏差与决策

T17.3 决策：(1) loading 态用「永不完成的 Future」(`Completer().future`) 驱动，且只 `pump()` 不 `pumpAndSettle()`（避免 CircularProgressIndicator 永久动画导致超时）。(2) 注入点选 `getCurrentUserUseCaseProvider`（最上游 bridge），覆盖它即可贯穿整条派生链（result → AsyncValue），演示「依赖在 provider 层替换」。
