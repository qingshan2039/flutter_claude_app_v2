# T16.2 配置 Git Hooks — 验证报告

> 任务 T16.2 / 模块 M16 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T16.2 用 lefthook 配置 git hooks：`pre-commit` 对暂存 .dart 做 `dart format`（自动回写）+ 全项目 `flutter analyze`；`commit-msg` 由 `scripts/check_commit_msg.sh` 校验 Conventional Commits。

## 1. 任务目标（来自 spec）

T16.2（spec 637-642）：集成 lefthook、pre-commit（format+analyze）、commit-msg（Conventional Commits 校验），交付物 `lefthook.yml`。

## 2. 实际配置

| hook | 动作 |
|---|---|
| pre-commit | `format`（glob `*.dart`，`dart format {staged_files}` + `stage_fixed`）+ `analyze`（`flutter analyze`），并行 |
| commit-msg | `bash scripts/check_commit_msg.sh {1}`：正则校验 type(scope)!: subject，放行 merge/revert/fixup |

## 3. 快速上手（Quick Start）

```bash
brew install lefthook   # 或 dart pub global activate lefthook
lefthook install        # 写入 .git/hooks
```

## 4. 验收命令与实际输出

```
$ bash scripts/check_commit_msg.sh <(echo 'feat(env): add staging flavor'); echo $?
0
$ bash scripts/check_commit_msg.sh <(echo '随便写的提交'); echo $?
❌ commit message 不符合 Conventional Commits 规范：...
1
```

（脚本对合法/非法消息分别返回 0/1。）

## 5. 与 spec 的偏差与决策

T16.2 决策：Conventional Commits 校验用独立 shell 脚本（`scripts/check_commit_msg.sh`）而非内联正则——便于本地手测与复用。未在本仓库执行 `lefthook install`（会改 `.git/hooks`，属本地动作）；`lefthook.yml` 与脚本为交付物。

## 6. 关键文件清单

| 文件 | 说明 |
|---|---|
| `lefthook.yml` | hook 配置 |
| `scripts/check_commit_msg.sh` | Conventional Commits 校验（可执行） |
