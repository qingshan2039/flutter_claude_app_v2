## 3. 快速上手（Quick Start）

T01.3 落地后，开发者实际使用方式：

### 3.1 提交前确认要 commit 的文件

```bash
# 列出 git 将要追踪的文件（须先 git init）
git ls-files --others --exclude-standard

# 检查某个具体路径是否被忽略
git check-ignore -v .dart_tool/package_config.json
# 预期: .gitignore:32:.dart_tool/    .dart_tool/package_config.json

# 检查某个文件的 attributes
git check-attr -a lib/main.dart
# 预期含: text: auto, eol: lf
```

### 3.2 添加 secrets 的正确方式

把 secrets 写到 `.env`（已被忽略），把字段示例写到 `.env.example`（白名单保留）：

```bash
# 创建一个团队成员可以复制的模板（会被提交）
echo "API_BASE_URL=https://api.example.com" > .env.example

# 创建本地 secrets（不会被提交）
cp .env.example .env
# 然后编辑 .env 填真实 key
```

`.gitignore` 第 「Secrets & Local config」 节会忽略所有 `.env*` 但保留 `.env.example` 与 `.env.template`。

## 6. 与 spec 的偏差与决策

T01.3 实施过程中做出以下与 spec 字面不完全一致、但与 spec 意图一致的设计决策。

### 6.1 决策一：生成代码默认不忽略（提供 opt-in 注释块）

- **spec 期望**: [flutter_template_v3.md:175](file:///Users/ben/Downloads/flutter_template_v3.md) 写「补充 IDE、临时文件、**生成产物**的忽略规则」
- **实际**: T01.3 把生成代码（`*.g.dart`、`*.freezed.dart`、`*.config.dart`、`*.gr.dart`、`*.mocks.dart`）放在 `.gitignore` 的 opt-in 注释块中，默认**不**忽略
- **理由**: Flutter / Dart 社区两派意见均成立。提交生成代码的好处：clone 后零配置即可 `flutter run`；CI 不需先跑 build_runner。不提交的好处：diff 干净。模板优先「零配置可跑」，并通过 `.gitattributes` 的 `linguist-generated=true` 让 PR review 时 GitHub 默认折叠生成文件 diff，间接获得不提交的视觉收益。
- **回退方法**: 取消 `.gitignore` 第 「Generated code (build_runner) — opt-in ignore」 节注释。

### 6.2 决策二：`.vscode/` 部分忽略而非全部

- **理由**: T15.4 在 M15 多环境配置中要求提交 `.vscode/launch.json`（三套环境启动配置），完全忽略 `.vscode/` 将阻挡该交付物。采用 `.vscode/*` + `!launch.json,!tasks.json,!extensions.json,!settings.template.json` 的白名单方式。

### 6.3 决策三：平台敏感文件不在根 `.gitignore` 重复

- **理由**: `flutter create` 已生成 `android/.gitignore`（14 行，含 `key.properties`、`**/*.keystore`、`**/*.jks`、`local.properties`）与 `ios/.gitignore`（34 行，含 `**/Pods/`、`xcuserdata`、`**/DerivedData/`、Flutter ephemeral 等）。这些规则**仅对其所在子树生效**，是 Git 的标准结构。在根 `.gitignore` 重复会产生维护负担。
- **影响**: 阅读根 `.gitignore` 的人需知道还有两份子目录 `.gitignore`。本任务在根文件的「Secrets」节加注释明确指向。

### 6.4 决策四：`.gitattributes` 的 `merge=union` 用于 `*.pbxproj`

- **理由**: iOS Xcode 工程文件 `project.pbxproj` 是常见的 merge 冲突源。`merge=union` 让 Git 尝试合并两侧所有行，减少（不消除）人工解决冲突的需要。这是 iOS 团队常用做法。

### 6.5 决策五：根 `.gitignore` 改写而非追加

- **理由**: Flutter 默认 49 行 `.gitignore` 无明显分节、注释，扩充后会更难维护。T01.3 完整重写为 23 节、200 行，所有原有规则全部保留（仅顺序与归类调整）。
