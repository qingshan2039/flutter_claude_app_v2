## 2. 设计要点

### 2.1 三层抽象 + 占位实现

| 抽象接口 | 占位实现 | 后续替换 |
|---|---|---|
| `TokenStorage` | `InMemoryTokenStorage` | M05/T05.2 → secure storage |
| `TokenRefresher` | `StubTokenRefresher`（永远抛 StateError） | M19/T19.1 → 调 `/auth/refresh` |
| `AuthEvents` | `NoopAuthEvents` | M19 → 路由跳转 + 清理本地数据 |

占位实现都加 `@LazySingleton(as: AbstractType)`，DI 中可直接解析，业务接入时**只需替换实现，不动 AuthInterceptor 自身**。

### 2.2 onRequest 行为

```dart
if (options.extra['skip_auth'] == true) return handler.next(options);
final token = await _storage.readAccessToken();
if (token != null) options.headers['Authorization'] = 'Bearer $token';
handler.next(options);
```

`skip_auth: true` 标记让 refresh 端点本身不要被 token 包裹（避免用旧 token 调 refresh 还是 401 的死循环）。

### 2.3 并发 401 共享同一次 refresh

用 `Completer<bool>?` 字段记录当前刷新会话：

```dart
if (_refreshCompleter != null) {
  // 已有刷新进行中，等同一结果
  refreshOk = await _refreshCompleter!.future;
} else {
  // 启动新刷新
  final completer = _refreshCompleter = Completer<bool>();
  refreshOk = await _performRefreshSession();
  completer.complete(refreshOk);
  _refreshCompleter = null;
}
```

10 个并发 401 → 第一个启动刷新，其余 9 个 `await` 同一 future → 刷新结束后全部用新 token 重发。

### 2.4 重试链路防递归

请求第二次走 onError 时检查 `extra['retried_after_refresh'] == true`：

```dart
if (err.requestOptions.extra['retried_after_refresh'] == true) {
  _events.onForcedLogout(cause: err);
  await _storage.clear();
  return handler.next(err);
}
```

避免新 token 仍然失效时的无限刷新-重试循环。

## 4. 实施过程的 Bug 修复

首版用 `_refreshCompleter.completeError(e, st)` 报告刷新失败。测试中 `refresh 失败 → onForcedLogout + clear` 失败：completer.completeError 后 future 错误没有任何监听者 → 触发「unhandled future error」让测试 runtime 标失败。

**修复**：把 `Completer<void>` 改为 `Completer<bool>`，刷新成功/失败都用 `complete(bool)` 报告，再由 onError 流程根据 bool 决定是否重试。完全规避 future 错误传播路径。
