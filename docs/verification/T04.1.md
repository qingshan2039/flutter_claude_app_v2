## 2. 设计要点

### 2.1 @module 注册模式

Dio 是第三方类，无法直接加 `@lazySingleton`。injectable 的 `@module` 模式可以注册工厂方法的返回值：

```dart
@module
abstract class NetworkModule {
  @lazySingleton
  Dio provideDio(TokenStorage, TokenRefresher, AuthEvents, LoggingInterceptor, RetryInterceptor, ApiErrorInterceptor) {
    final dio = Dio(BaseOptions(baseUrl: ..., connectTimeout: ...));
    final auth = AuthInterceptor(...);
    dio.interceptors.addAll([auth, log, retry, error]);
    auth.dio = dio;        // 回填，避免 DI 循环
    retry.dio = dio;
    return dio;
  }
}
```

### 2.2 BaseUrl 来源

```dart
const baseUrl = String.fromEnvironment('API_BASE_URL', defaultValue: 'https://api.example.com');
```

`--dart-define` 编译期注入，secrets 不入代码。M15/T15.1 EnvConfig 完成后改用 `getIt<EnvConfig>().apiBaseUrl`。

### 2.3 超时分级

| 项 | 值 | 说明 |
|---|---|---|
| connectTimeout | 10s | TCP 握手 |
| sendTimeout | 15s | 上传 body 总时长 |
| receiveTimeout | 20s | 等待响应 body |

### 2.4 拦截器顺序

```
[AuthInterceptor]    ← 注入 token / 处理 401（**最先**，确保 token 注入）
[LoggingInterceptor] ← 打印原始请求/响应
[RetryInterceptor]   ← 抖动重试
[ApiErrorInterceptor]← DioException → AppException（**最后**，给上层稳定类型）
```

### 2.5 DI 循环依赖处理

AuthInterceptor + RetryInterceptor 都需在 onError 中调 `dio.fetch` 重发。直接 `@lazySingleton` + 注入 Dio 会构成循环（Dio → Interceptor → Dio）。解决：

- 两者不在构造函数接收 Dio
- 暴露 `Dio? dio` setter
- 由 `provideDio` 在构造完 Dio 后回填
