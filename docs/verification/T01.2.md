## 3. 快速上手（Quick Start）

T01.2 完成后，新增功能的开发者只需了解三件事即可上手：

### 3.1 找位置

- 横向能力（网络、存储、错误、主题、日志、路由…）→ `lib/core/{模块}/`
- 通用 UI 组件 / 扩展 / 常量 → `lib/shared/{widgets,extensions,constants}/`
- 业务功能 → `lib/features/{业务名}/{data,domain,presentation}/`
- 国际化文案 → `lib/l10n/`

### 3.2 新增一个 feature（以 `profile` 为例）

```bash
mkdir -p lib/features/profile/{data,domain,presentation}
touch lib/features/profile/{data,domain,presentation}/.gitkeep
```

后续依次：`domain/` 写 entity + repository 接口 + usecase → `data/` 写 model + datasource + repository 实现 → `core/di/` 注册依赖 → `presentation/` 写 page + widget + provider → `core/router/` 加路由 → 删该 feature 下 `.gitkeep`。

### 3.3 placeholder 处理规则

当某目录下添加第一个 `.dart` 文件或资源时，**同步删除该目录下的 `.gitkeep`**。`.gitkeep` 仅为让空目录被 Git 追踪。

详见 [lib/README.md](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/README.md)。

## 5. 与 spec 的偏差与决策

T01.2 实施过程中有三处与 spec 第 4 节目录树的偏差。三处偏差均为有意而非疏漏，理由如下。

### 5.1 偏差一：未创建 `lib/app.dart`

- **spec 期望**: [flutter_template_v3.md:68](file:///Users/ben/Downloads/flutter_template_v3.md) 在树中列出 `lib/app.dart` 并注释「根 Widget」
- **实际**: T01.2 未创建
- **原因**: `app.dart` 的实际内容（含 `MaterialApp.router`、ThemeMode、Locale、ProviderScope 等）依赖 M06 状态管理、M07 路由、M08 国际化、M10 主题。在 T01.2 创建空 `app.dart` 会形成半成品，违反「不写半完成实现」的项目原则。
- **决策**: 留给 **M13 启动流程编排** 实施，由 T13.1 与 T13.2 一并产出。

### 5.2 偏差二：未创建 `lib/bootstrap.dart`

- **spec 期望**: [flutter_template_v3.md:69](file:///Users/ben/Downloads/flutter_template_v3.md) 在树中列出 `lib/bootstrap.dart` 并注释「启动初始化编排」
- **实际**: T01.2 未创建
- **原因**: 同 §5.1，`bootstrap.dart` 内容依赖 DI、Sentry、Logger、env 等模块；空 stub 无意义。
- **决策**: 由 **T13.1 编写 bootstrap.dart** 完成。

### 5.3 偏差三：`features/home/` 与 `features/settings/` 增加内部三层

- **spec 期望**: [flutter_template_v3.md:93-98](file:///Users/ben/Downloads/flutter_template_v3.md) 树中只在 `features/auth/` 下展示 `data/domain/presentation` 三层；`home/` 与 `settings/` 仅作 feature 占位
- **实际**: T01.2 在 `features/home/` 与 `features/settings/` 下也创建了 `data/`、`domain/`、`presentation/` 三个子目录
- **原因**: spec 标题明确「每个 feature 内部分层」（[flutter_template_v3.md:92](file:///Users/ben/Downloads/flutter_template_v3.md)），`auth/` 的三层结构是模板示例。T19.2（首页）与 T19.4（设置）需要相同结构。提前预置可让模板使用者直观看到「所有 feature 都按这个三层组织」，不必猜测。
- **决策**: 保留 home/ 和 settings/ 的内部三层。如果用户认为应严格遵循 spec 字面，可删除这 6 个子目录与对应 `.gitkeep`。

## 7. 设计决策记录

T01.2 在落地过程中做出以下设计决策，记录备忘：

- **采用 `.gitkeep` 而非 `README.md` 作为目录占位**：减少噪声。若每个叶子目录放一份说明性 README，会出现 28 份文档，与一份 `lib/README.md` 集中说明相比冗余且易腐烂。后续模块开始填充代码时，单一来源的 README 比 28 个分散 README 易维护。
- **`core/` 子目录与 spec 模块严格 1:1 映射**：让阅读 spec 的人能直接在源码中找到对应位置（M04 → `core/network/`）。
- **未创建 `app.dart` 与 `bootstrap.dart`**：避免半成品；M13 才有完整上下文写它们。
