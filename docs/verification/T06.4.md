## 2. 三层 Provider 链路设计

```
[DI 容器]               [Riverpod 树]
    ↓                       ↓
  getIt<GetCurrentUserUseCase>
    ↓
  ┌─ getCurrentUserUseCaseProvider     (Bridge: DI 暴露给 Riverpod)
  ↓
  ┌─ currentUserResultProvider          (Result<User>，业务可显式分支)
  ↓
  ┌─ currentUserProvider                 (AsyncValue<User>，UI 直接 when)
```

### 2.1 Bridge Provider

```dart
final getCurrentUserUseCaseProvider = Provider<GetCurrentUserUseCase>(
  (ref) => getIt<GetCurrentUserUseCase>(),
);
```

桥接 DI 与 Riverpod。生产从 `getIt` 取；测试中 override 为 fake。

### 2.2 Result 暴露层

```dart
final currentUserResultProvider = FutureProvider<Result<User>>((ref) async {
  final useCase = ref.watch(getCurrentUserUseCaseProvider);
  return useCase();
});
```

业务可直接 `ref.watch(currentUserResultProvider).whenData((r) => r.fold(...))`，显式处理 Success / Failed。

### 2.3 AsyncValue 拍平层

```dart
final currentUserProvider = FutureProvider<User>((ref) async {
  final result = await ref.watch(currentUserResultProvider.future);
  return result.fold(
    (user) => user,
    (failure) => throw _FailureException(failure),
  );
});
```

把 Failed 转抛异常，让 Riverpod 路由到 AsyncError。UI 用 `when(data:, loading:, error:)` 直接处理。

### 2.4 两种暴露层的取舍

- **业务关心 Failure 子类型**（如登录页区分 401 / 验证错误）→ 用 `currentUserResultProvider` 配合 fold
- **业务不关心错误细节，只需 loading/error/data 三态** → 用 `currentUserProvider` 配合 `when`

模板提供两种供使用者选择。

## 3. 与 spec 的偏差

spec 写「处理 Either&lt;Failure, T&gt; 返回值」。本项目 T03.3 选择自实现 `Result<T>`（含 `Success` / `Failed` 两个变体）替代 dartz Either，行为等价：

| spec 期望 | 本项目实际 |
|---|---|
| `Either<Failure, User>` | `Result<User>` |
| `either.fold(onLeft, onRight)` | `result.fold(onSuccess, onFailure)` |
| `Left(failure)` | `Failed(failure)` |
| `Right(value)` | `Success(value)` |
