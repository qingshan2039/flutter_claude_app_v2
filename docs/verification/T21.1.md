# T21.1 启动耗时埋点 — 验证报告

> 任务 T21.1 / 模块 M21 性能优化体系 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T21.1 实现 `StartupTracker`（`lib/core/logger/startup_tracker.dart`）：用 `Stopwatch` 记录从 `begin()` 起各命名阶段的累计耗时 + 增量，并记录**首帧时间**；集成进 `bootstrap.dart` 在 binding/di/envConfig/errorHandlers/runApp 各打点，首帧 `addPostFrameCallback` 里 `markFirstFrame()` 后用 `AppLogger` 打印 `summary()`。不依赖 DI（全局单例可在 DI 之前计时）。5 个单测全绿。

## 1. 任务目标（来自 spec）

T21.1（spec 842-845）：各阶段耗时记录 + 首帧时间，交付物启动埋点工具。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 阶段记录 | `StartupPhase{name, sinceStart, delta}`；`mark(name)` 追加阶段 |
| 首帧 | `markFirstFrame()` 记录首帧并追加 `firstFrame` 阶段（重复只取首次） |
| 不依赖 DI | `StartupTracker.instance` 全局单例，`begin()` 在 `configureDependencies` 之前调用（DI 耗时也被测） |
| bootstrap 打点 | binding → di → envConfig → errorHandlers → runApp → firstFrame |
| 输出 | 首帧后 `logger.i(startup.summary())` |
| 可测 | 纯 Dart 可实例化；测试用独立实例 + `reset()` |

## 3. 快速上手（Quick Start）

```dart
StartupTracker.instance.begin();          // bootstrap 入口
StartupTracker.instance.mark('di');       // 各阶段
StartupTracker.instance.markFirstFrame(); // 首帧
logger.i(StartupTracker.instance.summary());
```

showcase「M21 性能优化体系」页可直接看到本次启动的阶段耗时。

## 5. 与 spec 的偏差与决策

T21.1 决策：用**全局单例 + 可实例化**双形态——bootstrap 用 `instance`（需在 DI 前计时，无法靠 getIt），测试用独立实例避免全局状态污染。复用现有 `AppLogger` 输出，不引新依赖；与 M11 `PerformanceMonitor`（运行期 trace）职责区分：StartupTracker 专测启动链路。
