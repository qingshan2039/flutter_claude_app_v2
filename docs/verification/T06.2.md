## 3. 设计要点

### 3.1 显式命名

所有 Provider 都用 `name: 'xxxProvider'` 参数显式命名，配合 [AppProviderObserver]（T06.3）输出可读日志（否则只显示 `runtimeType`）。

### 3.2 StateNotifier vs Notifier

spec 字面提 "StateNotifier"。Riverpod 2.x 引入 `Notifier` 作为现代替代但 `StateNotifier` 仍受支持。T06.2 使用 `StateNotifier` 保持 spec 兼容；模板使用者可参考 [counter_state_notifier.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/features/examples/providers_demo/counter_state_notifier.dart) 顶部注释了解 Notifier 等价写法。

### 3.3 AsyncNotifier 展示三种状态切换

`UserAsyncNotifier` 实现：
- `build()` — 异步加载初始数据
- `refresh()` — 主动 reload（手动 loading → guard → data）
- `updateName(name)` — 同步 mutate 已有数据（不触发 loading）

让模板使用者看到 `AsyncValue` 状态机的常见操作。

### 3.4 autoDispose + family 一起用

`autoDisposeSearchProvider` 演示**最常见的组合**：搜索类页面，关键词改变即重算（family），离页就释放（autoDispose）。家族内不同 query 的实例互不干扰（测试验证）。
