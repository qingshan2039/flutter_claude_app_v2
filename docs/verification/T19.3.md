# T19.3 详情页模块 — 验证报告

> 任务 T19.3 / 模块 M19 示例业务模块 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T19.3 在 `features/detail/` 落地详情页：`DetailPage({required id})` 接路由参数 `id`，用 `articleDetailProvider`（`FutureProvider.autoDispose.family<ArticleDetail,String>`）异步加载，配 M14 `AsyncValueWidget` 渲染 loading/error/data 三态（error 带重试 `ref.invalidate`）。详情路由 `/detail/:id` 挂在 root navigator（跳出 Shell，无 BottomNav）。验收：analyze 0 issue、test 全绿、dev APK 构建成功。

## 1. 任务目标（来自 spec）

T19.3（spec 774-778）：详情页模块需覆盖**路由参数传递、异步数据加载、AsyncValue 三态**，交付物 `features/detail/`。

## 2. 实际配置

| 关注点 | 实现 |
|---|---|
| 路由参数传递 | `app_router.dart` `/detail/:id` → `DetailPage(id: state.pathParameters['id']!)`，`parentNavigatorKey: rootKey`（跳出 Shell） |
| 异步数据加载 | `articleDetailProvider = FutureProvider.autoDispose.family<ArticleDetail,String>((ref,id)=> ref.watch(detailRepositoryProvider).fetchDetail(id))` |
| 数据源 | `DetailRepositoryImpl.fetchDetail(id)`（stub：350ms 延迟；id=='error' 抛 `NetworkException` 演示错误态） |
| AsyncValue 三态 | `AsyncValueWidget<ArticleDetail>(value, onRetry: ()=>ref.invalidate(articleDetailProvider(id)), data: ...)` |
| 页面内容 | AppBar「详情 #$id」+ ListView（标题/作者/正文） |

## 5. 与 spec 的偏差与决策

T19.3 决策：用 `FutureProvider.family` 按 `id` 缓存与隔离（autoDispose 离页释放），而非手写 AsyncNotifier，最简表达「参数化异步」；详情数据为本地 stub。注意：`typed_routes.dart` 的 `/typed-detail/:id` 仍指向 router_demo 占位 DetailPage（未接线），故 `app_router_test` 的 typed-detail 用例仍断言旧文案——这是有意保留的演示对照。
