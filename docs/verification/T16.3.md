## 1. 任务目标（来自 spec）

## 2. 实际配置

| job | 触发 | 步骤 |
|---|---|---|
| analyze-and-test | PR + push | pub get → `dart format --set-exit-if-changed lib test` → `flutter analyze` → `flutter test` → build_runner 后 `git diff --exit-code`（生成物一致性） |
| build-android | push 到 main | setup-java 17 → 构建 `appbundle --flavor prod --obfuscate --split-debug-info` → upload-artifact |

含 `concurrency` 取消旧运行。

## 3. 快速上手（Quick Start）

推送 PR 即触发；本地等价：
```bash
dart format --output=none --set-exit-if-changed lib test
flutter analyze && flutter test
```

## 5. 与 spec 的偏差与决策

T16.3 决策：(1) Flutter 版本用 `channel: stable`，注释提示按需 `flutter-version` 固定（本机 Dart 3.11.5 属较新链，CI 模板默认 stable，使用者按 SDK 约束调整）。(2) 加「codegen 一致性」步骤：跑 build_runner 后 `git diff --exit-code`，确保提交的生成物是最新的。(3) main 构建用模板 `env/prod.example.json`；真实流水线应以 GitHub Secrets 注入 `env/prod.json` 与签名。
