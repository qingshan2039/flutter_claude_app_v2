# T14.2 异步状态封装 — 验证报告

> 任务 T14.2 / 模块 M14 通用 UI 组件 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T14.2 实现 `AsyncValueWidget<T>`：把 Riverpod 的 `AsyncValue` 三态（data/loading/error）统一映射到 T14.1 的状态组件，支持骨架屏 loading 与「刷新中保留旧数据」。`flutter analyze` 零问题，`test/shared/widgets/async_value_widget_test.dart` 全绿。

## 1. 任务目标（来自 spec）

T14.2 要求交付通用异步组件 `AsyncValueWidget`，处理 `AsyncValue` 三态（spec 589-592 行）。

## 2. 实际配置

| 维度 | 实现 |
|---|---|
| data | 调用 `data(value)` 构建器 |
| loading | 默认 `LoadingWidget.fullscreen`；`skeleton: true` 时用 `SkeletonLoader` |
| error | 默认 `AppErrorView(message, onRetry)`；可用 `error` 自定义 |
| 刷新优化 | `keepDataOnRefresh`（默认 true）：`isRefreshing && hasValue` 时展示旧数据，不闪 loading |

## 3. 快速上手（Quick Start）

```dart
final users = ref.watch(usersProvider);
AsyncValueWidget<List<User>>(
  value: users,
  onRetry: () => ref.invalidate(usersProvider),
  data: (list) => UserList(list),
  skeleton: true, // loading 用骨架屏
);
```

## 4. 验收命令与实际输出

```
$ flutter test test/shared/widgets/async_value_widget_test.dart
```

测试覆盖：data→data 构建器、loading→CircularProgressIndicator、loading+skeleton→SkeletonBox、error→AppErrorView + 重试回调。

## 5. 与 spec 的偏差与决策

T14.2 无偏差。决策：增加 `keepDataOnRefresh` 与 `skeleton` 两个开关，使下拉刷新场景（已有数据时再次请求）不出现整屏 loading 闪烁——这是 `AsyncValue.when` 默认行为的常见痛点。
