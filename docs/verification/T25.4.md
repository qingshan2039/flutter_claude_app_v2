# T25.4 网络状态监听 — 验证报告

> 任务 T25.4 / 模块 M25 离线优先架构 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T25.4 实现 `ConnectivityService`（抽象 + `@LazySingleton` 广播实现）：暴露 `status` + `onStatusChange` 流 + `setStatus()`（供 connectivity_plus 接入 / 测试 / demo），仅在状态实际变化时发射；并提供 Riverpod `networkStatusProvider`（StreamProvider，先发当前再跟随变化）= 网络状态全局通知。4 个单测全绿。

## 1. 任务目标（来自 spec）

T25.4（spec 984-987）：connectivity_plus 集成 + 网络变化全局通知，交付物网络状态 Provider。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 状态 | `NetworkStatus{online, offline}`（isOnline/isOffline 扩展） |
| 服务 | `ConnectivityService.status` + `onStatusChange`（broadcast）+ `setStatus()` + `dispose()` |
| 去重 | `setStatus` 相同状态不重复广播 |
| 全局通知 | `networkStatusProvider`（StreamProvider）先 yield 当前再 `yield*` 变化流 |
| connectivity_plus | `setStatus` 供生产侧用 `Connectivity().onConnectivityChanged` 喂入（文档示例） |
| DI | `ConnectivityService → ConnectivityServiceImpl`，`@disposeMethod` 关闭 controller |

## 3. 快速上手（Quick Start）

```dart
// 生产接入（在 bootstrap）：
Connectivity().onConnectivityChanged.listen((results) {
  final online = !results.contains(ConnectivityResult.none);
  getIt<ConnectivityService>().setStatus(
    online ? NetworkStatus.online : NetworkStatus.offline,
  );
});
// 消费：
final status = ref.watch(networkStatusProvider).valueOrNull;
if (status?.isOffline ?? false) showOfflineBanner();
```

## 5. 与 spec 的偏差与决策

T25.4 决策：不直接依赖 `connectivity_plus`，而用可注入/可控的 `ConnectivityService`（`setStatus` 供生产喂入、demo/测试模拟断网），零新增依赖且 demo 可手动切换离线——更利于演示离线优先。**踩坑修复**：`@disposeMethod` 让 injectable 生成 `dispose: (i) => i.dispose()`，但 `i` 是接口类型；最初未在 `ConnectivityService` 接口声明 `dispose()`，生成代码编译失败（`analysis_options` 排除 `*.config.dart` 故 analyze 未报，但 `flutter test` 编译报错）。已在接口补 `dispose()` 修复。
