T11.3 新建 [log_sanitizer.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/core/logger/log_sanitizer.dart)：`LogSanitizer` 用 4 条默认 `RedactionRule` 脱敏 password/token/secret/api_key（kv）、Bearer token、email（部分掩码）、手机号（保留前 3 后 2）；支持 `extraRules` 自定义。已接入 [AppLogger]（T11.1，每条消息输出前脱敏）。9 条测试覆盖各类脱敏 + 自定义规则。

## 1. 任务目标（spec）

- token / password / phone 等过滤
- 可配置规则
- **交付物**：脱敏过滤器

## 2. 默认规则

| 规则 | 模式 | 效果 |
|---|---|---|
| sensitive kv | `(password\|token\|secret\|api_key...):value` | 值 → `***` |
| Bearer | `Bearer xxx`（含 Authorization 头） | → `Bearer ***` |
| email | `alice@example.com` | → `a***@example.com` |
| phone | 7-15 位连续数字 | → `138****78` |

## 3. 可配置

```dart
final sanitizer = LogSanitizer(extraRules: [
  RedactionRule(pattern: RegExp(r'card-\d+'), replace: (_) => 'card-***'),
]);
```

`sanitize` 先跑默认规则再跑自定义规则。

## 4. 实施过程的 Bug 修复

测试 `Bearer token 脱敏` 失败：

```
Expected: contains 'Bearer ***'
  Actual: 'Authorization: *** eyJhbGciOiJIUzI1'
```

根因：`authorization` 在 kv 敏感键列表中，匹配 `Authorization: Bearer` 时把值 `Bearer`（空格前）当作敏感值替换成 `***`，反而留下了真正的 token。

**修复**：从 kv 规则移除 `authorization`（其值常含空格，如 `Bearer xxx`），由专用 Bearer 规则处理。修复后 `Authorization: Bearer eyJ...` → `Authorization: Bearer ***`，token 被正确脱敏。
