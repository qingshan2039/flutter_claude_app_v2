# T16.4 Android 打包脚本 — 验证报告

> 任务 T16.4 / 模块 M16 / 优先级 P0 / 状态 ✅ completed / 验证 2026-05-23

## TL;DR

T16.4 新增 `scripts/build_android.sh <flavor> [apk|aab]`：按 flavor 出 release 包，带 `--obfuscate --split-debug-info`；`build.gradle.kts` 增加从 `android/key.properties` 读取的正式签名（缺失回退 debug）。已用 `scripts/build_android.sh dev apk` 构建出 release APK 验证。

## 1. 任务目标（来自 spec）

T16.4（spec 651-655）：多 flavor 打包、签名配置，交付物 `scripts/build_android.sh`。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 多 flavor | `--flavor <env> -t lib/main_<env>.dart` |
| 格式 | apk / aab（appbundle） |
| 签名 | `signingConfigs.release` 读 `key.properties`（keyAlias/keyPassword/storeFile/storePassword）；缺失回退 debug |
| 混淆/符号 | `--obfuscate --split-debug-info=build/symbols/<flavor>` |
| 安全 | key.properties / *.jks / *.keystore 已在 android/.gitignore |

## 3. 快速上手（Quick Start）

```bash
# 配置正式签名（一次）：android/key.properties
#   storeFile=../keystore.jks
#   storePassword=... / keyAlias=... / keyPassword=...
scripts/build_android.sh prod aab     # 出 prod release AAB
scripts/build_android.sh dev apk      # 出 dev release APK
```

## 5. 与 spec 的偏差与决策

T16.4 决策：签名配置「有 key.properties 用正式签名，否则回退 debug」，保证未配置签名的本地/CI 也能跑通 release 流程；正式发布前必须提供 key.properties。脚本统一加混淆与符号拆分（与 T16.6 一致）。
