# T26.1 MethodChannel 封装 — 验证报告

> 任务 T26.1 / 模块 M26 原生互操作 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T26.1 实现 `MethodChannelClient`（通用封装：`invoke` 错误归一化、`invokeOr` 兜底不抛、`setCallHandler` 原生→Dart 回调）+ `DeviceBridge`（@LazySingleton 示例：Dart→原生取版本/电量 + 原生→Dart ping 双向）。错误统一为 `NativeUnavailableException` / `NativeCallException`。7 个 channel-mock 测试全绿。

## 1. 任务目标（来自 spec）

T26.1（spec 993-996）：双向调用示例 + 错误处理，交付物 MethodChannel 示例。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| Dart→原生 | `invoke<T>(method,[args])`；`MissingPluginException`→`NativeUnavailableException`、`PlatformException`→`NativeCallException(code,message)` |
| 兜底 | `invokeOr<T>(method, fallback)`：不可用/出错返回兜底（不抛） |
| 原生→Dart | `setCallHandler(handler)`（双向通信） |
| 示例 | `DeviceBridge.platformVersion()/batteryLevel()` + `onNativePing()`；未接入降级（unknown/-1） |
| channel | `flutter_claude_app/device` |

## 3. 快速上手（Quick Start）

```dart
final v = await getIt<DeviceBridge>().platformVersion();  // 未接入 → 'unknown'
getIt<DeviceBridge>().onNativePing((msg) => print('native: $msg'));
```

## 5. 与 spec 的偏差与决策

T26.1 决策：抽象 `MethodChannelClient` 复用错误处理与双向能力（与 M18/M23 的 channel seam 一致），业务用 `DeviceBridge` 这类领域桥；统一错误类型便于上层处理；channels 以名称标识，单测用 `setMockMethodCallHandler` 拦截。
