# T22.5 焦点管理 — 验证报告

> 任务 T22.5 / 模块 M22 无障碍 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T22.5 实现 `FocusManagementPage`：演示**显式 Tab 顺序**（`FocusTraversalGroup(OrderedTraversalPolicy())` + `FocusTraversalOrder(NumericFocusOrder(n))`——视觉顺序 A、C、B 而 Tab 顺序强制为 A→B→C）与**手动焦点**（`FocusNode.requestFocus()` / `FocusScope.unfocus()`）。接入 showcase「M22 无障碍」。3 个 widget 测试全绿（含模拟 Tab 键验证遍历顺序）。

## 1. 任务目标（来自 spec）

T22.5（spec 897-900）：键盘 Tab 顺序 + FocusNode 示例，交付物焦点管理示例。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| Tab 顺序 | `FocusTraversalGroup(policy: OrderedTraversalPolicy())` + `FocusTraversalOrder(order: NumericFocusOrder(1/2/3))` |
| 演示效果 | 视觉序 A、C、B → Tab 序 A→B→C（顺序脱离控件出现顺序） |
| 手动焦点 | `_jumpTarget.requestFocus()`；`FocusScope.of(context).unfocus()` |
| 资源释放 | 4 个 FocusNode 在 `dispose()` 释放 |
| 接线 | showcase「M22 无障碍」→「打开焦点管理示例」 |

## 5. 与 spec 的偏差与决策

T22.5 决策：用「视觉序 ≠ Tab 序」的对照（A、C、B vs A→B→C）直观演示 `NumericFocusOrder` 的价值；测试用 `tester.sendKeyEvent(LogicalKeyboardKey.tab)` 真模拟键盘遍历（而非直接调 API），更贴近真实键盘/辅助技术行为。
