# T28.1 远程配置抽象层 — 验证报告

> 任务 T28.1 / 模块 M28 远程配置与 Feature Flag / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T28.1 在 `core/remote_config/` 建立远程配置抽象：`RemoteConfig` 接口（类型化 getBool/Int/Double/String + getAll + fetchAndActivate）+ `RemoteConfigClient` 数据源接缝（Firebase/自建，含 `StubRemoteConfigClient`）+ `DefaultRemoteConfig`（@LazySingleton(as: RemoteConfig)，默认值打底 + 已激活值覆盖 + 本地缓存）。换数据源只改 DI 绑定。6 个单测覆盖。

## 1. 任务目标（来自 spec）

T28.1（spec 1039-1042）：RemoteConfig 接口 + 可切换实现（Firebase/自建），交付物 `core/remote_config/`。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 接口 | `RemoteConfig`：类型化 getter（带 defaultValue）+ getAll + fetchAndActivate |
| 数据源 | `RemoteConfigClient.fetch()`（Firebase/自建 接缝）→ `StubRemoteConfigClient` |
| 默认实现 | `DefaultRemoteConfig`（defaults 兜底 + activated 覆盖 + 类型强转 num→int/double） |
| 切换 | 改 `RemoteConfigClient`/`RemoteConfig` 的 DI 绑定（Firebase Remote Config / 自建 HTTP） |

## 3. 快速上手（Quick Start）

```dart
final title = getIt<RemoteConfig>().getString('welcome_title', defaultValue: '欢迎');
await getIt<RemoteConfig>().fetchAndActivate(); // 启动时刷新
```

测试覆盖：无缓存返回默认值；fetchAndActivate 激活远程值；num→int/double 强转；getAll 合并。DI：`RemoteConfig → DefaultRemoteConfig(RemoteConfigClient, KeyValueStorage)`、`RemoteConfigClient → StubRemoteConfigClient`。

## 5. 与 spec 的偏差与决策

T28.1 决策：不内置 Firebase SDK（避重依赖与平台配置成本），以「接口 + Client 接缝 + Stub」表达可切换；`DefaultRemoteConfig` 通用（自建后端只需实现 `RemoteConfigClient.fetch()` 返回 Map）。缓存与刷新见 [T28.4](T28.4.md)。
