# T25.1 缓存策略 — 验证报告

> 任务 T25.1 / 模块 M25 离线优先架构 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T25.1 实现 `CachePolicy`（networkFirst/cacheFirst/cacheOnly/networkOnly）+ `CacheStore`（KV-backed JSON，含 savedAt/TTL，@LazySingleton）+ `CachedFetcher`（@lazySingleton，按策略编排「缓存+网络」并在离线时回退缓存）。与具体网络库解耦（调用方传 networkFetch + 编解码）。10 个单测全绿。

## 1. 任务目标（来自 spec）

T25.1（spec 969-972）：网络优先/缓存优先/仅缓存 + dio_cache_interceptor 配置，交付物缓存策略示例。

## 2. 实际配置

| 策略 | 行为 |
|---|---|
| networkFirst | 在线取网络（失败回退缓存）；离线用缓存 |
| cacheFirst | 缓存新鲜则用；过期+在线取网络；过期+离线退陈旧缓存 |
| cacheOnly | 只读缓存，从不发网络 |
| networkOnly | 只发网络（在线）；离线无数据 |
| 存储 | `CacheStore`/`KeyValueCacheStore`：`{savedAt, data}` JSON；`CacheEntry.isStale(maxAge, now)` |
| 结果 | `CacheResult{data, source(network/cache/none), isStale}` |

## 3. 快速上手（Quick Start）

```dart
final r = await getIt<CachedFetcher>().fetch<List<Article>>(
  key: 'feed',
  policy: CachePolicy.cacheFirst,
  maxAge: const Duration(minutes: 5),
  isOnline: ref.watch(networkStatusProvider).valueOrNull?.isOnline ?? true,
  networkFetch: () => api.getFeed(),
  encode: (list) => list.map((a) => a.toJson()).toList(),
  decode: (json) => (json! as List).map(Article.fromJson).toList(),
);
```

## 5. 与 spec 的偏差与决策

T25.1 决策：未引入 `dio_cache_interceptor`，而实现**数据层通用缓存编排**（与网络库无关、可单测、可组合离线优先逻辑），并在文档/代码注释说明 `dio_cache_interceptor` 为 Dio HTTP 层缓存的生产选项。保持零新增依赖、零版本链风险（与模板既有 seam 策略一致）。
