# T27.1 埋点抽象层 — 验证报告

> 任务 T27.1 / 模块 M27 数据埋点 / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T27.1 在 `core/analytics/` 建立埋点抽象：`Analytics` 接口（logEvent/logScreenView/setUserId/setUserProperty）+ `NoopAnalytics`（关闭/未同意时）+ `LoggingAnalytics`（@LazySingleton(as: Analytics)，默认打到 AppLogger）+ `CompositeAnalytics`（同时上报 GA/友盟/神策 等多后端，单后端失败不影响其它）。业务只依赖接口，换后端只改 DI 绑定。

## 1. 任务目标（来自 spec）

T27.1（spec 1015-1018）：Analytics 接口定义 + 可切换实现（GA/友盟/神策），交付物 `core/analytics/`。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 接口 | `Analytics`：logEvent / logScreenView / setUserId / setUserProperty（均 Future） |
| 默认实现 | `LoggingAnalytics`（@LazySingleton(as: Analytics)，AppLogger.i） |
| 关闭实现 | `NoopAnalytics`（无副作用，配合 M24 同意门） |
| 多后端 | `CompositeAnalytics(List<Analytics>)` 并行 fan-out，try/catch 隔离 |
| 切换方式 | 改 `Analytics` 的 DI 绑定（注解 / @module），或注入 Composite 组合多后端 |

## 3. 快速上手（Quick Start）

```dart
getIt<Analytics>().logEvent('purchase', params: {'amount': 9.9});
// 多后端：
final analytics = CompositeAnalytics([GaAnalytics(), UmengAnalytics()]);
```

## 5. 与 spec 的偏差与决策

T27.1 决策：GA/友盟/神策不内置 SDK（避免重依赖与版本风险），而以「接口 + 适配 + Composite」框架表达——各后端实现 `Analytics` 适配类后用 `CompositeAnalytics` 组合，DI 一处切换。默认 `LoggingAnalytics` 便于 dev 观察埋点流。
