# T32.3 多模态上传 — 验证报告

> 任务 T32.3 / 模块 M32 AI 能力集成预留 / 优先级 P2 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T32.3 交付多模态附件三件套：`MediaAttachment`（名称/类型 image|audio/字节数 + `readableSize` 人类可读）、`MediaPicker` 抽象（`pickImage`/`pickAudio`，桩 `StubMediaPicker` 返回 null 不崩溃）、`AttachmentPicker` 组件（「添加图片/音频」按钮调 picker，已选附件以 chip 展示并可移除，`onChanged` 回传列表）。生产接 image_picker / file_picker 只改 DI 绑定。4 个单测全绿。

## 1. 任务目标（来自 spec）

T32.3（spec 1145-1147）：图片 / 音频上传组件，交付物多模态上传组件。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 附件模型 | `MediaAttachment{name, type(MediaType.image\|audio), sizeBytes, path?}` |
| 可读大小 | `readableSize` getter：B / KB / MB 自动换算（`500 B` / `2.0 KB`） |
| 选取抽象 | `abstract MediaPicker { pickImage(); pickAudio(); }`（返回 null = 取消） |
| 桩实现 | `StubMediaPicker`（`@LazySingleton(as: MediaPicker)`）两者返回 null（未接插件不崩溃） |
| UI 组件 | `AttachmentPicker{picker?, initial=[], onChanged?}`：picker 为空取 `getIt<MediaPicker>()` |
| 交互 | OutlinedButton.icon「添加图片/音频」→ picker；`Chip(onDeleted)` 移除；变更 `_emit()` 回传不可变列表 |

## 3. 快速上手（Quick Start）

```dart
AttachmentPicker(
  onChanged: (list) => _attachments = list, // List<MediaAttachment>
);
// 生产：DI 绑定真实 MediaPicker（image_picker/file_picker），组件无需改动
```

## 5. 与 spec 的偏差与决策

T32.3 决策：沿用本模板「抽象 + 桩 + 生产 seam」一致风格——`MediaPicker` 把 image_picker/file_picker/record 等插件差异隔离在接口后，桩实现返回 null 保证未接插件时 UI 仍可跑通与测试；`AttachmentPicker` 仅依赖 `MediaPicker` 抽象，`picker` 参数可注入（便于测试用 `_FakePicker` 注入合成附件，showcase 用 `_DemoMediaPicker` 返回演示附件）。`MediaAttachment` 与 LLM 请求解耦，可作为多模态消息的附件载荷上传。
