## 3. 设计要点

### 3.1 sealed class 二分

```dart
sealed class Result<T> {
  const Result();
}

final class Success<T> extends Result<T> {
  const Success(this.value);
  final T value;
  // ==/hashCode/toString
}

final class Failed<T> extends Result<T> {
  const Failed(this.failure);
  final Failure failure;
  // ==/hashCode/toString
}
```

- **为什么不用 freezed？** freezed 的泛型 sealed 配合 [Failure] 类型会让生成代码冗余；手写更轻量
- **为什么命名 `Failed` 而不是 `Failure`？** 与 [failures.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/core/error/failures.dart) 中的数据类 `Failure` 区分（避免引入歧义）
- **为什么不用 `Either<L, R>`？** dartz/fpdart 增加依赖；`Result<T>` 与 [Failure] 紧耦合更贴合本项目领域

### 3.2 扩展方法（七件套）

| API | 签名 | 语义 |
|---|---|---|
| `fold` | `R fold<R>(R Function(T) onSuccess, R Function(Failure) onFailure)` | 收敛到单一类型 |
| `map` | `Result<R> map<R>(R Function(T) transform)` | 仅成功时变换 |
| `flatMap` | `Result<R> flatMap<R>(Result<R> Function(T) transform)` | 链式调用下一个 Result |
| `isSuccess` | `bool get` | 类型谓词 |
| `isFailure` | `bool get` | 类型谓词 |
| `valueOrNull` | `T? get` | 成功取值，失败 null |
| `failureOrNull` | `Failure? get` | 失败取 Failure，成功 null |

所有实现用 Dart 3 switch expression + 模式匹配：

```dart
R fold<R>(R Function(T) onSuccess, R Function(Failure) onFailure) {
  return switch (this) {
    Success<T>(value: final v) => onSuccess(v),
    Failed<T>(failure: final f) => onFailure(f),
  };
}
```

## 4. 快速上手

### 4.1 在 Repository 中使用

```dart
class AuthRepository {
  AuthRepository(this._dataSource, this._mapper);
  final AuthRemoteDataSource _dataSource;
  final ErrorMapper _mapper;

  Future<Result<User>> getCurrentUser() async {
    try {
      final model = await _dataSource.fetchCurrentUser();
      return Success(model.toEntity());
    } on Exception catch (e) {
      return Failed(_mapper.map(e));
    }
  }
}
```

### 4.2 在 Provider 中链式处理

```dart
final result = await ref.read(authRepoProvider).getCurrentUser();

// 模式 1：fold 收敛为 widget
return result.fold(
  (user) => UserCard(user),
  (failure) => ErrorView(failure),
);

// 模式 2：map 变换
final Result<String> name = result.map((u) => u.name);

// 模式 3：flatMap 链式
final Result<Profile> profile = result.flatMap((u) => loadProfile(u.id));

// 模式 4：pattern matching（最直观）
switch (result) {
  case Success(:final value): showUser(value);
  case Failed(:final failure): showError(failure);
}
```

## 6. 与 spec 的偏差与决策

### 6.1 决策一：选择自定义 `Result<T>` 而非 dartz `Either`

- **理由**:
  1. dartz 维护放缓；fpdart 是替代品但仍是 3rd-party
  2. Dart 3 sealed class + switch expression 足以表达 Either 语义，且类型推导更友好
  3. `Result<T>` 名字与 [Failure] 强语义绑定，比通用 `Either<L, R>` 更直接
- **代价**: 缺少 fpdart 提供的 `Option`、`IO` 等其他 FP 工具。本项目暂不需要

### 6.2 决策二：失败变体命名 `Failed<T>` 而非 `Failure<T>` 或 `Error<T>`

- **理由**: 避免与 [Failure] 数据类同名；`Error` 是 Dart 内置类型，更易混淆
- **替代**: 也可用 `Err<T>`（Rust 风格），但 `Failed<T>` 在 Dart 社区更易读
