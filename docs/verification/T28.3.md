# T28.3 Kill Switch — 验证报告

> 任务 T28.3 / 模块 M28 远程配置与 Feature Flag / 优先级 P1 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T28.3 实现 `KillSwitch`（@lazySingleton，读 RemoteConfig 的 `app_kill_switch`/`app_kill_message`）+ `KillSwitchGate` 组件：激活时用全屏 `ForcedOfflineScreen`（图标 + 文案 + 可选重试）拦截整个 App，否则透传 child。支持 `active`/`message` 覆盖用于 demo/测试。7 个单测/widget 测试全绿。

## 1. 任务目标（来自 spec）

T28.3（spec 1049-1052）：紧急下线开关 + 强制下线 UI，交付物 Kill Switch 实现。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| 开关 | `KillSwitch.isActive`（`app_kill_switch`）/ `message`（`app_kill_message`，带兜底） |
| 强制下线 UI | `ForcedOfflineScreen`（Material 包裹：cloud_off 图标 + 标题 + 文案 + 重试） |
| 门 | `KillSwitchGate({child, killSwitch?, active?, message?, onRetry?})` |
| 接入 | `MaterialApp(builder: (c, child) => KillSwitchGate(child: child!))` |
| 懒解析 | active/message 被覆盖时不触碰 DI（getIt） |

## 3. 快速上手（Quick Start）

```dart
MaterialApp(
  builder: (context, child) => KillSwitchGate(
    onRetry: () => getIt<RemoteConfig>().fetchAndActivate(),
    child: child!,
  ),
);
```

## 5. 与 spec 的偏差与决策

T28.3 决策：Kill Switch 复用 RemoteConfig（运营远程开关，无需发版），`ForcedOfflineScreen` 用 Material 包裹以便全屏或内嵌（demo 内嵌预览）；`KillSwitchGate` 懒解析 KillSwitch，使 `active`/`message` 覆盖时无需 DI（便于测试/预览）。生产可在文案中引导更新（结合 M23）。
