# T32.2 流式响应 — 验证报告

> 任务 T32.2 / 模块 M32 AI 能力集成预留 / 优先级 P2 / 状态 ✅ completed / 验证 2026-05-24

## TL;DR

T32.2 交付流式响应两件套：`SseParser`（纯函数解析 SSE 文本块——`event:`/`data:` 多行合并/`:` 注释忽略/`[DONE]` 哨兵）与 `StreamingTextView`（订阅 `Stream<String>` 增量分片，逐片累积显示、未结束带光标 `▌`、结束回调 `onDone` 并去光标）。两者厂商无关，配合 T32.1 的 `LlmClient.stream` 实现逐字打字机效果。8 个单测全绿。

## 1. 任务目标（来自 spec）

T32.2（spec 1140-1143）：SSE / WebSocket 封装 + 流式 UI 组件，交付物流式响应模块。

## 2. 实际配置

| 项 | 实现 |
|---|---|
| SSE 事件模型 | `SseEvent{event, data, isDone}`（`isDone` = `data == '[DONE]'`） |
| SSE 解析 | `abstract final SseParser.parse(String chunk)`：按 `\n\n` 分事件，处理 `event:` / `data:`（多行合并）/ `:` 注释 |
| 流式 UI | `StreamingTextView{required Stream<String> stream, style?, showCursor=true, onDone?}` |
| 累积 | `StringBuffer` 逐片 `write`；`didUpdateWidget` 在 stream 变更时取消旧订阅、清空、重订阅 |
| 光标 | 未结束且 `showCursor` 时尾部追加 `▌`，`onDone` 触发后去光标 |
| WebSocket | 接口层面用同一 `Stream<String>` 抽象；SSE 为本模板默认（LLM 主流），WS 可同样接入 StreamingTextView |

## 3. 快速上手（Quick Start）

```dart
// 把 LlmClient.stream 的分片映射成 Stream<String> 喂给 UI
final deltas = getIt<LlmClient>().stream(req).map((c) => c.delta);
StreamingTextView(stream: deltas, onDone: () => debugPrint('done'));

// 解析后端 SSE 原始块
for (final e in SseParser.parse(rawChunk)) {
  if (e.isDone) break; // [DONE]
  buffer.write(e.data);
}
```

## 5. 与 spec 的偏差与决策

T32.2 决策：（1）`SseParser` 设计为**无状态纯函数**（`static parse`），按 `\n\n` 切完整事件，便于单测且可组合进任意传输层（Dio `ResponseBody.stream` 或 WebSocket）；（2）`StreamingTextView` 只依赖 `Stream<String>` 而非 `LlmChunk`，与厂商/协议彻底解耦——LLM 流、SSE delta、WS 文本都能直接驱动；（3）组件测试中流是异步投递，断言前用 `await tester.pumpAndSettle()` 排空微任务与帧，确保累积文本可见（单次 `pump()` 可能漏投递第二片）。
