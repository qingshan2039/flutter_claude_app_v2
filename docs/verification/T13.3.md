# T13.3 异步并行初始化优化 — 验证报告

> **任务 ID**: T13.3 · **模块**: M13 启动流程编排 · **优先级**: P0 · **状态**: ✅

## TL;DR

T13.3 在 [bootstrap.dart](file:///Users/ben/ai_project/flutter_claude_app_v2/lib/bootstrap.dart) 中区分**关键路径**（阻塞首帧）与**非关键路径**（首帧后延迟）：DI/存储/错误处理是关键路径，await 后才 runApp；日志清理/缓存预热/远程配置等非关键工作放 `addPostFrameCallback` → 首帧渲染后执行，不拖慢启动。

## 1. 任务目标（spec）

- 拆分关键路径与非关键路径
- 非关键依赖延迟初始化
- **交付物**：优化后的 bootstrap

## 2. 关键 vs 非关键

| 类别 | 内容 | 时机 |
|---|---|---|
| **关键路径** | binding 初始化、`configureDependencies`（含 SharedPreferences/Hive @preResolve）、全局错误处理 | await，阻塞首帧 |
| **非关键路径** | 日志文件清理（M11）、缓存预热、远程配置拉取（M28）、埋点初始化（M27） | `addPostFrameCallback` 首帧后 |

## 3. 实现

```dart
// 关键：await 后才 runApp
await configureDependencies(environment: ...);
registerGlobalErrorHandlers(reporter: report);
runApp(...);   // 首帧

// 非关键：首帧后延迟，不阻塞启动
WidgetsBinding.instance.addPostFrameCallback((_) {
  unawaited(_initDeferred(logger));
});
```

`_initDeferred` 包 try/catch：非关键初始化失败**不影响**应用可用性（仅 warn 日志）。

## 4. 设计取舍

- **为何不全 await**：把所有初始化堆在首帧前会拉长白屏时间。用户感知的「启动快」= 首帧出现快。非关键工作晚几百毫秒无感。
- **DI 内部已并行**：`configureDependencies` 的 `@preResolve`（SharedPreferences + AppDatabase）由 injectable 生成的 `init` 串行 await；如需进一步并行，可在 module 中用 `Future.wait`。当前存储初始化耗时小，未额外并行。
- **接入点预留**：`_initDeferred` 留好注释，M11 文件日志清理、M27 埋点、M28 远程配置落地后挂到此处。
