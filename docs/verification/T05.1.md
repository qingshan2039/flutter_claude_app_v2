## 2. 设计要点

### 2.1 接口与实现分离

抽象 `KeyValueStorage` 不依赖 SharedPreferences。这让上层 Repository 只与抽象耦合，未来想切换到 hive 或测试桩只需提供新实现。

### 2.2 sync get + async set

SharedPreferences 启动后内存缓存数据，get 是同步。set 是 async（写入磁盘）。本接口照原样暴露这种异构性：

```dart
String? getString(String key);                          // sync
Future<bool> setString(String key, String value);       // async
```

不强行包装成全异步，避免业务调用方多余的 `await`。

### 2.3 通过 @module 处理 async 初始化

SharedPreferences 的 `getInstance()` 是 async。要让 DI 容器统一管理需要用 `@module` + `@preResolve`：

```dart
@module
abstract class SharedPreferencesModule {
  @preResolve
  @lazySingleton
  Future<SharedPreferences> get prefs => SharedPreferences.getInstance();
}
```

`configureDependencies()` 内部 `await` 这个 future，确保上层注入 SharedPreferences 时已就绪。`SharedPreferencesStorage` 构造函数同步接收 `SharedPreferences` 实例。
