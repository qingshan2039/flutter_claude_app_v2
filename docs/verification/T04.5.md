## 2. 设计要点

### 2.1 重试分类（shouldRetry）

公开方法便于业务覆写。**只重试幂等/瞬时类**：

```dart
bool shouldRetry(DioException err) {
  switch (err.type) {
    case DioExceptionType.connectionTimeout:
    case DioExceptionType.receiveTimeout:
    case DioExceptionType.sendTimeout:
    case DioExceptionType.connectionError:
      return true;
    case DioExceptionType.badResponse:
      final status = err.response?.statusCode ?? 0;
      return status >= 500 && status < 600;
    case _:
      return false;
  }
}
```

4xx 不重试：客户端错误重发还是错。`badCertificate` 不重试：证书问题不会因重试解决。`cancel` 不重试：用户主动取消应尊重。

### 2.2 指数退避 + 抖动

```dart
Duration computeBackoff(int attempt) {
  final base = baseDelay * pow(2, attempt).toInt();           // 500ms / 1s / 2s / 4s ...
  final jitter = random.nextInt(baseDelay.inMilliseconds);   // 0~500ms
  return base + Duration(milliseconds: jitter);
}
```

加抖动避免「重试风暴」（所有客户端同时退避同时重试）。

### 2.3 尝试计数存储在 RequestOptions.extra

```dart
final attempt = (err.requestOptions.extra['retry_attempt'] as int?) ?? 0;
if (attempt >= maxRetries) return handler.next(err);
options.extra['retry_attempt'] = attempt + 1;
```

存在 extra 而非实例字段：**并发请求互不干扰**。

### 2.4 dio 反向引用

需调用 `dio.fetch(options)` 才能让重发请求重走整个拦截器链（auth 重新注入 token 等）。通过 setter 在 `provideDio` 中回填：

```dart
late Dio? dio;
```

避免 DI 循环（Dio → RetryInterceptor → Dio）。

## 4. 实施过程的 Bug 修复

首版构造函数：

```dart
RetryInterceptor({this.maxRetries = 3, this.baseDelay = ..., Random? random}) : _random = random ?? Random();
```

`injection.config_builder` 抱怨：

```
[RetryInterceptor] depends on unregistered type [Random] , from dart:math
Did you forget to annotate the above class(s)?
```

injectable 看到构造函数有 `Random?` 参数但 DI 容器里没有 Random 实例。**修复**：把 `random` 从构造函数移到公开字段，默认值 `Random()`，测试可写 `interceptor.random = Random(42)` 注入确定性 seed。
